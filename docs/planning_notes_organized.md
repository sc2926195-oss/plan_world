# 轨迹规划学习笔记（整理版）

> 依据 `~/桌面/规划学习.txt` 整理：重排结构 + 术语修正 + 补充，并映射到我们的
> **plan_world USV 入港走廊规划**问题（只生成路径/走廊，不做运动控制）。
> 用途：复习框架、对齐术语，后续选定实现路线时对照。

---

## 0. 总框架

```
轨迹规划 = 路径规划（几何层） + 轨迹优化（时间/平滑层）
```

- **路径规划**：先回答“能不能到、走哪条折线/点列”——输出一串无碰撞的航路点。
- **轨迹优化**：把折线拟合成平滑、连续、无碰撞、带时间的曲线——输出“什么时刻在什么位置/以什么姿态”。
- 两者之间往往还有一层**安全走廊（corridor）**：把“无碰撞”从点级约束升级成“整段都在一个安全通道内”的约束。

## 1. 路径规划（离散 / 几何层）

### 1.1 基于搜索（需要先把空间离散成格栅或图）

| 算法 | 要点 | 补充/修正 |
|---|---|---|
| Dijkstra | 加权图上的单源最短路，像“洪水扩散”，按累计代价从小到大扩展 | 需要优先队列；网格代价均匀时退化为 BFS |
| BFS | 广度优先，无权图上能保证最短 | 时间复杂度高主要因为它不考虑代价/启发，只逐层扩 |
| A* | Dijkstra + 启发式：按 `f = g(已走代价) + h(到目标估计代价)` 扩展 | **本质是 Dijkstra 的启发式加速**，不是“BFS 上位替代”；h 需可采纳(admissible)/一致(consistent)才保证最优 |

> 对我们场景：100×100 m，若 1 m 格栅就是 1 万个节点——对 A*/Dijkstra 来说其实很小
> （毫秒级），真正的代价是**分辨率/离散化**：5 m 宽的泊位口、贴障碍转弯这些细节会被
> 网格抹掉。这也是你想用采样法的一个正当理由，但“1 万格太复杂”本身不是瓶颈。

### 1.2 基于采样（连续空间，无需全图离散）

- **RRT**：随机采样、向最近节点扩展树，快但路径不是最优、且很毛糙（折线到处拐）。
- **RRT\***：在 RRT 基础上，新节点加入时**在邻域内重选更优父节点 + 重连邻居**（局部成本
  优化），随迭代次数增加趋于最优（“渐近最优”）。笔记里“相当于对节点做了一次局部
  Dijkstra”这个直觉方向对，准确说法是**邻域内的父节点重选与重连**。
- **Informed RRT\***：**先找到一条可行解后**，把后续采样限制在以起点/终点为焦点的
  **椭圆**（高维是超椭球）内，集中采样“可能比当前解更短”的区域，收敛更快、路径更优。
  - 注意：它依赖“先有一条解”，所以实现上通常是“普通 RRT* 先跑出首解 → 再切到椭圆采样”。

### 1.3 基于智能算法（把路径编码成个体/解，迭代搜索）

- **遗传算法 (GA)**：大量路径（种群）→ 选择（按适应度，好的留、坏的淘汰概率大）→
  交叉（交换两条父代路径的片段生成新路径）→ 变异（随机取两点、重连/扰动中间段）→ 循环。
  - 笔记基本正确；补充：需要先有“如何表示一条路径”的编码，且要处理交叉/变异后路径
    可能穿越障碍的修复。
- **蚁群 (ACO)**：笔记里“BFS + 信息素”不准确。更准确：**在图上**一群蚂蚁按
  “启发信息 + 信息素浓度”概率性地走，走过的好路径留下更多信息素，形成正反馈，最终收敛到
  较好路径。它仍是基于**离散图**的，不是连续空间直接采样。

> 小结：连续水域、稀疏障碍、目标点少 → 采样法(RRT*/Informed RRT*)最自然；
> 智能算法更多用于图已建好后的组合优化，对我们的问题属于“可以做但绕远”。

## 2. 轨迹优化（时间 / 平滑层）

输入：路径点列 + 起终点状态 + 速度/曲率等限制；输出：带时间的平滑曲线。

### 2.1 轨迹表示方法

- **（分段）多项式曲线**：以时间为参数的 piecewise polynomials。
  - 各阶导有明确物理意义（一阶=速度、二阶=加速度…），容易**精确满足端点/中间点的
    位置+速度+加速度约束**。
  - 最小化 jerk(3 阶)/snap(4 阶) 就是让加加速度/冲击小，曲线更顺、更容易被底层跟踪。
- **贝塞尔曲线 (Bézier)**：由控制点定义，次数=控制点数−1。
  - 关键性质：**凸包性**——整条曲线都被限制在控制点的凸包内。只要控制点都在安全走廊内，
    曲线就“一定”不出去（充分条件，很实用）。
  - 首尾精确通过两端点；多段拼接时要额外处理段间导数连续。
- **B 样条 (B-spline)**：贝塞尔的推广，**局部支撑**（移动一个控制点只影响附近一小段），
  工程上常用均匀 B 样条做平滑/拟合，同样有凸包性质，段间连续性容易控制。
- 三者关系：贝塞尔是 B 样条的特例；做“整条走廊内平滑”时 B 样条/贝塞尔靠凸包性最省心，
  做“精确端点速度/加速度 + 最小化冲击”时分段多项式更直接。

### 2.2 优化目标

- 最小化 jerk / snap（平滑性、可执行性）
- 最小化轨迹长度 / 总时间 / 能量（可加权组合）
- 笔记里“轨迹长度”作为目标没问题，注意长度目标会倾向“抄近道切角”，要与安全/曲率约束平衡。

### 2.3 约束

- **硬约束**：必须满足——走廊/凸包内（安全）、端点状态、速度/加速度/曲率限幅等。
- **软约束**：尽量满足——离障碍远一点、控制量小一点等，用惩罚项写进目标。
- 修正笔记一句：走廊约束通常是**硬约束**（把走廊写成线性不等式/凸包约束），
  “离障碍的距离”才常被写成软约束惩罚。

## 3. 术语修正速查表（对照你的原笔记）

| 原笔记表述 | 修正/更准确表述 |
|---|---|
| BFS 是 A* 上位替代 | A* 是 **Dijkstra 的启发式改进**；BFS 只是无权图最短路 |
| RRT* 差不多等于对节点做 dijkstra（一定范围内） | RRT* = **邻域内父节点重选 + 重连**的局部成本优化，渐近最优 |
| Informed RRT* 是“压缩采样范围（椭圆压缩）” | 需**先有首条解**，再把采样约束到以起终点为焦点的椭圆内加速收敛 |
| 蚁群 = BFS + 信息素 | ACO = 图上的**概率行走 + 信息素正反馈**，依赖离散图 |
| 轨迹优化 = 多项式/贝塞尔 + 最小化snap/长度 | 更完整的表述见第 2 节：表示(多项式/Bézier/B样条) + 目标(jerk/snap/长度/时间) + 约束(硬/软) |
| 贝塞尔“递推求曲线” | de Casteljau 递推只是求值方式；更重要性质是**凸包性、端点插值、段间连续性** |

## 4. 映射到我们的问题（plan_world 入港走廊规划）

- 场景：100×100 m 开放水域（ENU，水面 z≈0）；10 个静态随机障碍（正三角/正方形，~10 m²，
  高 0.6 m）；3 座 U 形浮动泊位于北侧 (0/50/100, 100)，内净空 **5 m(宽) × 7 m(深)**，开口朝南；
  起点 (50, 0)，初始朝北（指向 (50,100) 的港口）。
- 任务（你已确认）：**不做运动控制**，只生成“平滑 + 无碰撞 + 可入港”的路径，再膨胀成比船
  稍宽的**走廊**。船“理论上”能沿走廊开进港即可。
- 由此得到的规划要点：
  1. **状态空间 2D 就够**：(x, y)；障碍与港口墙体在二维水面投影上处理。
  2. **膨胀方向**：最省事且严谨的写法是——把每个障碍/墙体按“走廊半宽”膨胀成 C-space
     障碍，然后让**中心线**避开膨胀障碍；这样走廊自动无碰撞。另一种是先生成走廊再逐段查
     碰撞，两者等价但前者更干净。
  3. **终点航向**：入港最后一段必须沿泊位轴线（朝北/+Y），且走廊宽度必须 < 泊位内宽 5 m
     （建议走廊半宽 = 船半宽 ~1.25 m + 0.25~0.5 m 余量 ≈ 1.5~1.75 m，即走廊宽 3~3.5 m，
     在港内两侧各留 ~0.75~1 m）。
  4. **运动学**：WAM-V 是双推进器差速，**可原地转向** → 全路径没有“硬性最小转弯半径”
     （不像汽车/固定翼）；曲率只做**软上限**即可，不必上 Dubins/Reeds-Shepp。
  5. **三个港口** = 同一规划器跑 3 次（不同终点），或一棵树长出 3 条分支后分别提取；
     前者简单、互不干扰，建议先做前者。

## 5. 推荐实现路线草图（供学习/选型对照）

```
[1] Informed RRT* ×3（起点 → 每个港口入港段起点/港中心）
       ↓
[2] 路径简化 + 平滑（B样条 / 贝塞尔 / 分段多项式，端点航向对齐）
       ↓
[3] 走廊生成：平滑中心线 ± 走廊半宽；或“障碍按半宽膨胀 + 中心线校验”
       ↓
[4] 校验：碰撞 / 走廊宽 / 曲率 / 入港末段为直线且对齐泊位
       ↓
[5] 输出 + 显示（matplotlib 图 / JSON；Gazebo 用 marker 或纯视觉模型，见下）
```

- 每步失败就回退（平滑切角撞了 → 重采样/重新平滑；走廊进不了港 → 调整目标点/余量），
  所以**每一步都要有可复现的输出和校验脚本**，别一把梭到最后。

## 6. 你选的“Informed RRT* + 轨迹 + 走廊”路线的建议/注意点

1. **Informed RRT\* 输出是折线**，必须再平滑；平滑后要**重新做碰撞/走廊校验**（曲线会切角）。
2. 若用贝塞尔/B 样条：把**控制点约束在走廊内**，靠凸包性保证曲线不出走廊——比“先画曲线再
   逐点检查”更稳。若用分段多项式：走廊写成线性不等式，配合 QP/数值优化解硬约束。
3. 入港段建议单独处理成“**直航道**”：目标点取港中心 (x,100)、航向 +Y，最后 7 m 保持直线
   且宽度 < 5 m；不要让随机采样曲线在港内乱扭。
4. 障碍数据真值已在 `my_plan_world/obstacles_meta.json`（世界系多边形），规划器直接读它 +
   `port_berth` 几何即可，不需要在仿真里“感知”。
5. 显示（见 README 配套说明 / 下方第 8 节）建议先 matplotlib/RViz 调试，Gazebo 只做最终展示。

## 7. 建议下一步补的知识点（按优先级）

1. **配置空间 / 膨胀 / 碰撞检测**：多边形 vs 圆/多边形 vs 多边形的判定（做校验必须）。
2. **曲率与转向**：`κ = |x'y'' − y'x''| / (x'²+y'²)^{3/2}`；差速船 `R = v/ω`，原地转向即 R→0。
3. **贝塞尔/B 样条的凸包性与拼接连续性**（做“走廊内平滑”的核心工具）。
4. **Informed RRT\* 的实现细节**：最近邻、邻域重连、椭圆采样（先普通 RRT* 出首解再切换）。
5. 若走多项式+QP：分段多项式轨迹 + 走廊线性不等式（对应飞行器 min-snap 思路，但船用
   min-jerk/曲率约束即可）。
6. （了解即可）Dubins/Reeds-Shepp、Hybrid A*、state-lattice——它们解决“有最小转弯半径/离散
   动作”的问题，我们目前用不到，但知道边界在哪有帮助。

## 8. 在 Gazebo 里显示走廊：技术选项速记

- **选项 A（推荐，轻量）**：gz-sim **Marker**——纯 GUI 渲染、无物理。向 marker 服务发
  `gz.msgs.Marker`（单条）或 `Marker_V`（批量，服务名通常带 `_array`）。走廊画成：
  半透明 TRIANGLE_LIST 带状面片（z≈0.2，高于波浪） + 中线/边界 LINE_STRIP + 起终点/泊位口
  标记。plan_world 的 GUI 里已经带 `MarkerManager` 插件，无需改世界。
  发送方式：小 C++ 节点用 gz-transport 调 Request，或命令行 `gz service`/`gz topic`；ROS 2 侧
  `ros_gz_bridge` 默认**没有** Marker 映射，不能直接用 ROS 话题发。
- **选项 B（最稳）**：把走廊做成**纯视觉静态模型**（只有 `<visual>`、没有 `<collision>`、
  `<static>true</static>`），运行时用 `/world/plan_world/create` 服务（`EntityFactory`）插入，
  重规划时 `/remove` 再插。VRX 自己 spawn 船就是用 `ros2 run ros_gz_sim create`，这条链路
  已被验证过。
- **选项 C（调参期最舒服）**：RViz2 显示 `visualization_msgs/MarkerArray` + `nav_msgs/Path`，
  Gazebo 只保留仿真。规划调试推荐先用 C，最终展示用 A/B。
- 波浪注意：水面随波浪起伏，走廊面片放在**固定 z≈0.1–0.3** 即可，视觉上略浮于波面是正常的。
